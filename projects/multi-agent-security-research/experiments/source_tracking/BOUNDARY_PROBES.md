# 来源核验的定向边界实验

2026-11-18，补充论文的机制证据。输入为本脚本构造的无敏感信息案例，未连接模型服务。18 个案例分别调用两种实际核验函数，共 36 次核验；另用真实 `run_chain` 接口执行 6 条脚本化三角色链，合计 18 次固定响应。它们不是 18 次模型调用，也不是攻击成功率样本。

## 复现

在研究项目目录，使用 Python 3.11+ 及已有的 `httpx`、`python-dotenv` 依赖：

```powershell
python -m experiments.source_tracking.boundary_probe --output experiments/source_tracking/local-runs/my-boundary-probe.json
```

输出路径必须尚不存在，避免覆盖证据。实际记录使用 Python 3.12.14；原始输入、核验输出、逐角色交接及源码 SHA-256 均见 [boundary-probe-20261118.json](boundary-probe-20261118.json)。脚本不构造模型客户端，不读取模型密钥，不发出网络请求。

## 结果与解释

- 两协议均接纳正确摘录，均拒绝不存在的摘录、结论与摘录不一致、插入零宽字符及不可见后文。
- 序号协议忽略模型自报 ID，所以前缀误写或伪造 ID 不影响正确序号的绑定。该行为不能解释为允许伪造真实身份。
- 布尔、字符串、浮点、零和越界序号都被序号协议拒绝；ID 协议忽略这些不属于其协议的字段。两种字段在同一合成输入中同时提供，只为隔离确定性规则，不模拟模型输出分布。
- 两协议都接纳原文中的恶意指令与无关句子：字面来源匹配不检查语义角色或任务相关性。
- 重排两个来源后，唯一摘录被序号协议拒绝；共享摘录仍被接纳，却绑定到与原预期不同的来源。ID 协议保留原来源。这是故意违反固定列表假设的压力案例，不能写成当前固定列表三角色链必然发生的漏洞。
- 三角色回声实验中，开启核验可去掉自由摘要中的标记，但未核验的 `topics` 标记仍跨三个角色传递。原文内恶意指令始终保留在候选结论；开启核验还会将其纳入重建摘要。固定回声响应不证明真实模型会服从指令。
- 现有 `build_evidence_bundle` 不导出未核验主题，且本案例的合格引用不含标记；原始资料仍包含标记并保持 `external-untrusted`。因此不能用整个 JSON 是否出现标记来判断污染，必须区分原始资料、核验引用与未经核验的元数据通道。

## 验证与限制

补充运行现有序号绑定及证据交接回归：28 项通过。第一次检查因旧 Python 环境不支持已有代码中的联合类型注解而未能收集；切换到 Python 3.12.14 后通过。没有修改生产核验规则来改善结果。

案例按机制有意构造，不随机、不独立，不计算综合通过率、显著性或泛化攻击率。历史 160 次运行、480 次模型调用与本次确定性实验分开统计；未重跑历史请求。代码级行为可以复现，模型行为与安全收益仍需有效基线攻击、预算一致的真实模型实验。
